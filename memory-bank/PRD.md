# CS-PhD-Hiring

小红书 CS 相关博士招生广告的可检索汇总站。产品形态参考 [DuoOffer](https://duooffer.github.io/)，采集方法参考 [CityU-CS-Guide](https://github.com/null1024-ws/CityU-CS-Guide)。

## Target user

准备申请 CS / AI 相关 PhD 的学生。他们现在要同时刷小红书、一亩三分地和导师主页，信息散、难筛，且公开汇总里的学校/导师字段经常对不上。

## User problem

1. 小红书上大量老师/学生转发 CS 招生帖，但没有按学校、方向、国家可筛的公开索引。
2. DuoOffer 解决了「可筛表格」问题，但数据主要来自一亩三分地和主动提交；用户要的是小红书这一源。
3. 同类汇总里 **PI 所属学校经常错**（同名老师、转校、帖子只写方向不写学校、抽取把合作单位当成任职单位）。本项目要把「学校可核对」当成一等公民，而不是事后备注。

## Primary user flows

1. 打开站点，按国家/地区、学校、研究方向、入学学期筛选招生条目。
2. 点开一条，看导师、学校、方向、招生学期、原文摘录，并跳转小红书原帖核对。
3. 维护者登录小红书 CLI，按关键词采集新帖，流水线抽取结构化字段、校验学校、去重后重建静态站。
4. 访客通过 GitHub Issue/PR 补一条漏网广告，经校验后进入同一表格。

## Major features

- 小红书关键词搜索 + 笔记详情采集（复用 CityU-CS-Guide 的 `xhs-cli` / Camoufox、断点续跑、限速、交叉检索）。
- 从正文（及必要时图片 OCR）抽出：导师姓名、学校、国家/地区、研究方向、入学学期、联系方式、原帖链接、采集时间。
- **学校校验**：抽取结果不得直接信任；需对照导师主页或其它公开来源，标记 `verified` / `unverified` / `conflict`。
- 去重：同一导师 + 同一招生周期合并，保留多条原帖来源。
- 可筛选静态站点（GitHub Pages），每条可回跳原帖。
- 过滤明显非招生帖、科研中介帖、非 CS 相关帖。中介帖外表可以很正常甚至诙谐，不能靠语气判断；正文（含图内 OCR）里不敢放自己的邮箱或主页，是主要信号。

## Decisions (clarified)

- **机会类型**：不限 PhD。PhD / 直博 / RA / Postdoc / 科研型硕士 / intern（科研实习、暑研、访问）都收。目标是让读者发现「有这个老师」。
- **地理**：全球，含内地。
- **学科**：以 CS / AI / 系统 / 安全 / HCI / 机器人为核心；边界案例由流水线按规则判断（强计算/方法导向可收，纯实验/非计算方向不收）。
- **入库**：小红书自动采集 + GitHub Issue/PR 补条。
- **学校校验**：自动对照主页或公开资料；对不上仍展示，标记 `unverified` / `conflict`。
- **站点**：列表是可筛表格；详情页用 CityU-CS-Guide 那套纸感排版。
- **图片**：v1 必须 OCR，招生信息经常只在图里。
- **科研中介**：不看是否「像广告」。正文 + 图片 OCR 中不敢出现发帖人自己的邮箱或学术主页，再叠加私信/微信引导，则按中介丢掉。评论区里的联系方式不算「介绍自己」。

## Key constraints / assumptions

- 数据源默认只有小红书，不一亩三分地为源；DuoOffer 只作交互与字段参考。
- 采集依赖本机 `xhs-cli` 登录态；Cookie 不入库。
- 公开站点只发布结构化摘要 + 原帖链接，不镜像完整笔记图文。
- 学校字段错误是已知失败模式，流水线必须显式处理，不能只靠一次 LLM/正则抽取。
- 站点应能在无后端的情况下部署（静态站优先）。
- 信息来自社区帖，非官方；页面需免责声明。
